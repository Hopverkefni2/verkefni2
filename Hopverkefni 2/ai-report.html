02 · Grunnur verkefnisins

Tækni og ákvarðanir

HTML, CSS og JavaScript án ramma

HTML lýsir innihaldi síðunnar, CSS útlitinu og JavaScript hegðuninni. Verkefnið er skrifað án React eða annars viðmótsramma. Nú er JavaScript-kóðinn skrifaður í TypeScript og þýddur í script.js; vafrinn keyrir áfram venjulegt JavaScript. Þetta heldur keyrsluumhverfinu einföldu og gerir grunnkóðann læsilegan, en verkefnið er ekki lengur án byggingarskrefs.

index.html · script.js hleðsla

<script src="script.js" defer></script>

defer lætur vafrann sækja skrána án þess að stöðva HTML-lesturinn og keyra hana eftir lestur skjalsins.

Sömu skrár tengdar við síðurnar

Allar HTML-síðurnar hlaða sama style.css og script.js. Haus og fótur eru endurtekin sem HTML á síðunum, ekki sett í sameiginlegt íhlutakerfi. JavaScript virkni sem á bara við tiltekna síðu byrjar þegar samsvarandi auðkenni finnst; leit og uppáhald nota sínar eigin tilvistarskoðanir. Það minnkar hættu á að formkóði reyni að nota reit sem er ekki á síðunni.

function initBusinessProfile(businessList: Business[]): void {
  const businessRoot = document.getElementById("biz-root");
  if (!businessRoot) return;
  // ...
}

style.css · kaflaskipting

/* ===== Header ===== */
.site-header {
  background: var(--color-white);
  padding: 20px 0;
}

/* ===== Hero ===== */
.hero {

  grid-template-columns: 1fr 1fr;

Ástæða: auðvelt er að finna stíla og hegðun eftir síðu eða eiginleika, án þess að bæta við ramma eða byggingarkerfi fyrir íhluti.

CSS-breytur

Sérsniðnar CSS-breytur geyma litina í :root. Þær eru notaðar víða, svo breyting á skilgreiningu getur uppfært marga hluta í einu.

Þetta passar verkefninu þar sem sami litapallettur birtist á forsíðu, síum, formum og prófílum.

Grid skipuleggur tvívíð svæði eins og kort og dálka. Flexbox raðar hlutum í eina stefnu og leyfir þeim að vefjast þegar pláss minnkar.

  gap: 20px;

Þessi verkfæri henta kyrrstæðri vefsíðu þar sem kort, form og upplýsingadálkar þurfa að raðast ólíkt eftir breidd.

Skölun og brotpunktar

CSS er að mestu skrifað út frá stærra skjáútliti og þrengt með max-width media queries. Kóðinn notar 1024 px og 768 px víða, 480 px fyrir uppáhaldskort og 400 px fyrir nokkrar almennar stillingar. Því er ekki rétt að segja að allar síður hafi nákvæmlega þrjá sameiginlega brotpunkta. Brotpunktar eru settir þar sem útlit verkefnisins þarf að breytast; sú aðferð hentar líka hönnun sem hófst á stærra Figma-borði.

style.css · sími

@media (max-width: 768px) {
  .hero {
    grid-template-columns: 1fr;
    min-height: 0;
  }
  .categories {
    grid-template-columns: repeat(2, 1fr);
  }
}

localStorage fyrir uppáhald

localStorage er geymsla í vafranum sem helst eftir að flipi lokast. Hún geymir lista af auðkennum fyrirtækja undir lyklinum tint-favorites. Umsagnir notenda eru vistaðar undir lyklinum tint-reviews sem hlutur með auðkenni fyrirtækis sem lykil, og eru því aðeins sýnilegar í vafranum þar sem þær voru skrifaðar. Geymslan er ekki samstillt á milli vafra eða tækja og hún tengir ekki uppáhald eða umsagnir við innskráðan notanda.

script.ts · geymslulykill

const FAVORITES_KEY = "tint-favorites";

Þetta er einföld leið til að halda vali notanda á þessari vefsíðu án gagnagrunns.

URLSearchParams og deilanleg ástand

URLSearchParams les eða býr til fyrirspurnargildi aftan við ? í vefslóð. Verkefnið notar id fyrir prófíl, flokkur og leit fyrir fyrirtækjalistann. Flokkur og leit eru uppfærð með history.replaceState, án þess að endurhlaða síðuna.

script.ts · lesa upphafsval

const parameters = new URLSearchParams(window.location.search);
const initialQuery = parameters.get("leit") ?? "";
state.query = initialQuery;

Það gerir auðveldara að senda öðrum hlekk á ákveðið fyrirtæki eða upphafsleit.

TypeScript og strangar týpur

TypeScript bætir týpum við JavaScript og þýðandinn leitar að ósamræmi áður en vafrinn keyrir kóðann. Verkefnið notar tsc til að þýða script.ts í script.js, sem HTML heldur áfram að hlaða. strict virkjar strangari týpuskoðun; noImplicitAny bannar að týpur falli ósjálfrátt í any. files takmarkar þýðinguna við script.ts. TypeScript var valið vegna kröfu námskeiðsins og til að greina mistök fyrr.

tsconfig.json · mikilvægustu stillingar

"target": "ES2020",
"lib": ["ES2020", "DOM", "DOM.Iterable"],
"strict": true,
"noImplicitAny": true,
"removeComments": false,
"sourceMap": false,
"skipLibCheck": true,
"files": ["script.ts"]

script.ts · gildissvið flokka og viðskipta

type Category = "snyrti" | "fatnadur" | "heimilid" | "skartgripir" | "matur";
type StoreType = "verslun" | "netverslun" | "bæði";
type Tag = "baekur" | "gjafir" | "heimilid" | "handgert" | "skartgripir" | "tiska";

interface Review {
  name: string;
  date: string;
  stars: number;
  text: string;
}

Business lýsir fyrirtækjahlutnum: meðal annars id, name, category, storeType, tags, heimilisfangi, opnunartíma, tenglum, myndum og reviews: Review[]. Einkunn og fjöldi umsagna eru ekki geymd í gögnunum heldur reiknuð með calculateRating(). Týpurnar ná ekki sjálfkrafa að sannreyna JSON við keyrslu; gögnin eru staðfest með TypeScript-casti í hleðslufallinu, ekki keyrslutíma-prófi.

fetch, async/await og init

fetch sækir gögn í gegnum HTTP frá JSON-skránni. Promise er gildi sem verður tiltækt síðar; await bíður eftir því inni í async falli. response.ok greinir hvort HTTP-svarið tókst. try/catch grípur net- og svarvillur, skráir þær og birtir íslensk villuboð þar sem fyrirtæki eiga að birtast.

script.ts · loadBusinesses

async function loadBusinesses(): Promise<Business[]> {
  try {
    const response = await fetch("data/businesses.json");
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return await response.json() as Business[];
  } catch (error: unknown) {
    console.error("Gat ekki sótt fyrirtækjagögn:", error);
    showBusinessLoadError();
    throw error;
  }
}

script.ts · init bíður eftir gögnunum

async function init(): Promise<void> {
  try {
    businesses = await loadBusinesses();
  } catch {
    return;
  }
  updateFavoritesBadge();
  onFavoritesChange(updateFavoritesBadge);
  const search = initSearch(businesses);
  initFavoritesPage(businesses);
  initExplorePage(businesses, search);
  initBusinessProfile(businesses);
}

JSON-skrá og TypeScript-kóði eru aðskilin eins og gögn og notkun þeirra væru aðskilin API. Síðan verður að vera opnuð á vefþjóni, til dæmis Live Server eða Netlify; vafrar leyfa almennt ekki fetch á file://.

3.3 Fréttabréf

Prófa á síðunni →

Hvað gerir þetta og hvernig er það notað?

Gestur slær inn netfang á forsíðu og velur „Skrá mig“. Rangt netfang fær villuboð og fókus færist aftur í reitinn. Rétt netfang skiptir forminu út fyrir þakkarskilaboð. Skráningin er ekki send á netþjón eða póstlista.

Skrár og kóði

index.html notar newsletter-form, email, email-error og newsletter-wrap. script.ts notar initNewsletter().

script.ts · staðfesting netfangs

const isValid = EMAIL_RE.test(emailInput.value.trim());
if (!isValid) {
  errorMessage.hidden = false;
  emailInput.setAttribute("aria-invalid", "true");
  emailInput.focus();

Hvernig virkar kóðinn?

Ef það stenst ekki er villukaflinn sýndur og aria-invalid sett. Ef það stenst býr kóðinn til staðfestingarelement og setur það í newsletter-wrap.

3.4 Leit og tillögur

Prófa á síðunni →

Hvað gerir þetta og hvernig er það notað?

Gestur getur leitað á öllum síðum. Þegar hann skrifar birtast allt að sex tillögur auk tengils á allar niðurstöður. Niðurstöður í fyrirtækjanöfnum fá forgang. Örvatakkar velja tillögu, Enter opnar hana og Escape lokar listanum. Leitin finnur til dæmis „Bakað“ þegar slegið er „bakad“.

Skrár og kóði

Leitarformið form.search og search-input er í HTML-síðunum. script.ts notar normalizeText(), searchBusinesses(query, list), highlightName() og initSearch(). CSS notar .search-dd, .search-dd-row og .is-active.

script.ts · íslenskir stafir samræmdir

function normalizeText(text: string): string {
  return text.toLowerCase().normalize("NFD").replace(/[\u0300-\u036f]/g, "")
    .replace(/ð/g, "d").replace(/þ/g, "th").replace(/æ/g, "ae").replace(/ö/g, "o");
}

Hvernig virkar kóðinn?

Leit er upphafsstillt eftir að init() sækir gögnin. input bíður 150 ms og teiknar tillögur. keydown sér um örvar, Enter og Escape. Tillögurnar eru HTML-hlekkir í role="listbox"; leitarreiturinn fær role="combobox". Smellur utan formsins lokar listanum. Leitarfallið samræmir íslenska stafi, skiptir fyrirspurn í orð og krefst þess að hvert orð finnist í nafni eða upplýsingum. Hlekkur „Sjá allar niðurstöður“ sendir leit með í fyrirtaeki.html.

1. Gestur skrifar fyrirspurn.
2. input keyrir leit eftir stutta bið.
3. searchBusinesses() raðar samsvörunum.
4. DOM-ið fær tillögur og Lucide-táknin eru teiknuð.

Af hverju passar þetta verkefninu?

Ein leit styttir leið að litlum fyrirtækjum og þolir stafsetningarmun sem fylgir íslenskum stöfum. Lyklaborðsstýring gerir sama verkflæði aðgengilegt án músar.

3.5 Öll fyrirtæki

Hvað gerir þetta og hvernig er það notað?

Gestur sér fyrirtækjakort og getur sameinað leit við flokk, staðsetningu, tegund verslunar og merki. Hann getur líka raðað nöfnum A–Ö eða Ö–A. Ef ekkert passar birtist skilaboð og „Hreinsa síur“ hnappur. Flokkur og leit birtast í slóðinni.

script.ts · skilyrði síanna

const matchesFilters = (business: Business): boolean =>
  (state.category === "all" || business.category === state.category) &&
  (state.location === "all" || business.location === state.location) &&
  (state.type === "all" || business.storeType === "bæði" || business.storeType === state.type) &&
  (state.tags.size === 0 || business.tags.some((tag) => state.tags.has(tag)));

Hvernig virkar kóðinn?

Við upphaf les initExplorePage() leit og flokkur úr slóðinni. Atburðirnir click á pillum og fellilistum og change á merkjum breyta sameiginlegu síuástandi. render() leitar fyrst, beitir síðan öllum síum saman, raðar ef óskað er og uppfærir teljara, kort og tóma stöðu. history.replaceState skrifar leit/flokk í slóðina án endurhleðslu. Tegundin „bæði“ passar við bæði valin fyrir verslun og netverslun.

1. Gestur velur síu eða skrifar leit.
2. Atburðahleri uppfærir state.
3. Leit og allar síur keyra saman.
4. Kort, teljari, tóma staða og slóð endurnýjast.

script.ts · vista / taka af lista

function toggleFavorite(id: string): boolean {
  const currentFavorites = getFavorites();
  const nowFavorite = !currentFavorites.includes(id);
  const nextFavorites = nowFavorite
    ? [...currentFavorites, id]
    : currentFavorites.filter((favoriteId) => favoriteId !== id);
  memoryFavorites = nextFavorites;
  try {
    localStorage.setItem(FAVORITES_KEY, JSON.stringify(nextFavorites));
  } catch {
    // Keep the in-memory copy when browser storage is unavailable.
  }
  updateFavoritesBadge();
  return nowFavorite;
}

04 · Samvinna við gervigreind

Aðferð við promptun

Samkvæmt lýsingu hópsins var Claude notað til að breyta Figma-myndum og stílaleiðbeiningum í skipulögð fyrirmæli og GitHub Copilot í Agent mode í VS Code til að skrifa og breyta kóða. Figma-skjáskot voru látin fylgja og sagt að viðhengið væri aðalviðmið. Einnig voru tilgreind skráarnöfn, myndaslóðir, tenglar, auðkenni og íslenskur texti til að minnka ágiskanir.

Þegar viðmótsviðmið voru á ensku var texti þýddur á íslensku og sömu fimm flokkar notaðir á síðunum. Unnið var í lotum: niðurstöður bornar saman við fyrirmæli og beðið um afmarkaðar leiðréttingar, meðal annars á umsóknarformi, tengiliðasíðu og uppáhaldssíðu. Gögn voru færð í sameiginlegt gagnasafn og einn prófílsniðmátssíða notuð í stað sérstakrar HTML-síðu fyrir hvert fyrirtæki.

Lærdómur

  • Í fyrri verkefnavinnu eyddi Copilot skrám með terminal skipun. Eftir það voru fyrirmæli um að eyða eða endurskapa engar skrár nema það væri sérstaklega beðið um það.
  • Terminal-skipanir sem breyttu skrám með línunúmerum voru erfiðar að afturkalla. Hópurinn fór því að óska eftir breytingum beint í ritlinum og að vista Git-útgáfu fyrir áhættusamar breytingar.
  • Hópurinn lærði að lesa skipanir áður en þær eru samþykktar: Get- skipanir lesa gögn, en Remove-, WriteAllLines, Set-Content og Add-Content breyta skrám.
  • Þegar tengiliðasíðan virtist röng var ástæðan að CSS-breytingarnar höfðu ekki verið samþykktar með „Keep“. Lærdómurinn var að samþykkja breytingar og endurhlaða með Ctrl+F5 áður en leitað er að öðrum villum.
  • Uppáhaldsvirknin er útskýrð hér út frá núverandi kóða. Orsök fyrri bilunar er ekki skráð í verkefnisskrám og er því ekki giskuð.

07 · Notkun fyrir sem flesta

Aðgengi

Í kóðanum eru nokkrar aðgengisráðstafanir sem hægt er að benda á:

  • Merkt form: reitir tengjast <label for="...">; leit og fréttabréf hafa einnig falin, læsileg label.
  • Ástand stjórntækja: síur og hjörtu nota aria-pressed; leitartengill notar role="combobox", fellilistinn role="listbox" og valkostirnir role="option". Fellivalmyndir nota aria-expanded.
  • Uppfærslur: fjöldi fyrirtækja er í aria-live="polite"; formkvittanir fá role="status" og netfangsvilla role="alert".
  • Myndtextar: forsíðumyndir, flokkamyndir og fyrirtækjakort hafa alt-texta. Skrautmyndir í leitarniðurstöðum nota tóman alt-texta.
  • Lyklaborð og fókus: leit styður örvar, Enter og Escape; CSS sýnir :focus-visible-útlínur.

08 · Það sem er eftir

Takmarkanir og næstu skref

  • Form senda engin gögn: umsókn, samskipti og fréttabréf sýna aðeins staðfestingu í vafranum. Fyrirtækjagögnin eru í data/businesses.json og sótt með fetch; uppáhald er geymt í localStorage í vafranum. Enginn netþjónn eða gagnagrunnur tekur við formgögnum.
  • Uppáhald er staðbundið: localStorage er bundið við vafra/tæki og engin innskráning er til. Innskráning og gagnagrunnur gætu samstillt listann.
  • Fyrirtæki og umsagnir eru sýnidæmi: JSON inniheldur verkefnagögn, ekki staðfest raungögn. Einkunn er reiknuð úr þeim umsögnum sem eru til staðar, þar með töldum umsögnum notenda sem vistaðar eru í vafranum. Næst þyrfti gagnaveitu og ferli til að sannreyna upplýsingar.
  • Uppsetning á Netlify er handvirk: README lýsir drag-and-drop uppfærslu. Sjálfvirk birting eftir yfirfarið Pull Request gæti stytt útgáfuferlið.
  • Ytri tenglar fyrirtækja eru sýnigildi: mörg website, instagram og facebook gildi eru # í JSON. Raunverulegar slóðir þarf að fylla inn áður en tenglarnir nýtast.
  • JSON er ekki sannreynt við keyrslu: as Business[] er TypeScript-cast, ekki prófun á raunverulegu svari. Schema-prófun gæti stöðvað gögn með rangri gerð áður en þau eru birt.
  • Letur: CSS nefnir Amarna en HTML hleður aðeins Freeman frá Google Fonts. Hægt er að hlaða Amarna sérstaklega ef það er enn markmiðið.
  • Myndabilanir: grár CSS-bakgrunnur er til staðar en engin onerror-varamynd. Hægt væri að bæta við aðgengilegri varamynd og villumeðhöndlun.
  • Figma-slóð og söguleg verkefnaskipting: liggja ekki fyrir í núverandi README. Bætið þeim við þegar hópurinn hefur staðfest rétt gildi.
